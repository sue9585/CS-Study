### 🗂️ 자료구조: Balanced Tree (AVL, Red-Black) (최묘석, 김영웅 발표)

*   **왜 필요한가**: BST는 정렬된 값을 순서대로 넣으면 편향되어 O(N)으로 퇴화합니다. 균형 트리는 높이를 **O(log N)** 으로 묶어 탐색·삽입·삭제의 최악 시간을 보장합니다.
*   **AVL 트리**: 균형 인수 `BF = 왼쪽 높이 - 오른쪽 높이`가 모든 노드에서 -1, 0, +1이어야 합니다. 깨지면 **회전 4종(LL, RR, LR, RL)** 으로 복구합니다. 회전은 값이 아니라 부모·자식 연결만 바꾸므로 BST 대소 관계가 유지됩니다.
    *   삽입: 회전 한 번(단일 또는 이중)이면 위쪽까지 균형이 맞춰집니다.
    *   삭제: 회전 후 서브트리 높이가 줄 수 있어 루트까지 올라가며 반복합니다. 회전이 최대 O(log N)번 일어날 수 있습니다.
*   **Red-Black 트리**: 5가지 규칙(빨강/검정, 루트 검정, NIL 검정, 빨강 연속 금지, 모든 경로의 검정 수 동일)으로 가장 긴 경로가 가장 짧은 경로의 2배를 넘지 않게 **느슨하게** 유지합니다.
    *   삽입: 새 노드는 빨강으로 넣고, 부모도 빨강이면 **삼촌**을 봅니다. 삼촌이 빨강이면 **Recoloring**(위로 반복), 검정이면 **Restructuring**(회전 후 종료, 최대 2번).
    *   삭제: 검정 노드를 지우면 검정이 1개 모자란 **Double Black**이 생기고, **형제**를 보고 해결합니다. "형제에게 빌릴 빨강이 있으면 회전, 없으면 부모로 넘긴다." 회전은 최대 3번입니다.
*   **자식이 2개인 노드 삭제**: 바로 지우지 않고 **중위 후속자**(오른쪽 최솟값)로 값을 교체한 뒤 후속자 노드를 대신 지웁니다. 후속자는 왼쪽 자식이 없어 항상 자식이 0~1개이고, 균형 복구는 실제로 지워진 후속자 자리에서 시작합니다. (2회차 BST 삭제 내용과 연결)
*   **AVL vs Red-Black**: 둘 다 O(log N)이지만 AVL은 엄격해서 탐색이 빠르고, RB는 느슨해서 삽입·삭제 때 회전이 적습니다.
*   **실무 연결**
    *   **Java TreeMap**: RB 트리. `deleteEntry()`가 후속자 교체 → 실제 삭제 → `fixAfterDeletion()` 순서로 동작하고, `ceilingKey()`도 후속자 찾기와 같은 원리입니다.
    *   **DB 인덱스(B+트리)**: 페이지가 비면 형제에게서 빌리거나 병합 후 부모로 넘깁니다. RB 삭제와 비슷한 발상이고, 대량 DELETE를 나눠 실행하거나 소프트 삭제(`deleted_at`)를 쓰는 이유 중 하나입니다.
    *   **리눅스 CPU 스케줄러**: 가장 왼쪽(가장 덜 실행된) 프로세스를 꺼내 실행합니다. 삽입·삭제가 매우 잦아 RB가 유리합니다.

### 🌐 네트워크: TCP vs UDP / Handshake / TCP 제어 / 포트 포워딩 (조수연, 권혜강 발표)

*   **TCP vs UDP**: IP는 "어느 컴퓨터로", 포트는 "어느 프로그램으로"를 정합니다. TCP는 연결 지향이고 재전송·순서 보장·흐름/혼잡 제어를 하며 헤더가 20~60바이트입니다. UDP는 비연결이고 헤더가 8바이트라 가볍습니다. DNS, 게임, 음성·영상 통화, QUIC에 쓰입니다.
*   **3-way Handshake**: `SYN(seq=x)` → `SYN+ACK(seq=y, ack=x+1)` → `ACK(ack=y+1)`. 서로의 준비 상태와 초기 순서 번호(ISN)를 확인합니다. ISN은 옛 패킷과 섞이거나 예측당하지 않도록 무작위로 정합니다.
    *   2번이 아닌 이유: 서버가 자기 번호가 닿았는지 확신할 수 없고, 늦게 도착한 옛 SYN에 속아 연결을 열 수 있습니다.
*   **4-way Handshake**: `FIN` → `ACK` → (남은 데이터) → `FIN` → `ACK`. TCP는 양방향을 따로 닫기 때문에 ACK와 FIN을 합치지 못합니다(Half-Close).
    *   **CLOSE_WAIT**가 서버에 쌓이면 코드에서 소켓을 안 닫은 버그일 가능성이 큽니다.
    *   **TIME_WAIT**: 먼저 끊은 쪽이 2MSL 동안 기다립니다. 마지막 ACK 유실 대비, 늦게 온 옛 패킷이 새 연결에 섞이는 것 방지. 대량으로 쌓이면 포트가 부족해지므로 Keep-Alive, 커넥션 풀로 재사용합니다.
*   **TCP 제어 기법**: 지키는 대상이 다릅니다.
    *   흐름 제어(수신자): 슬라이딩 윈도우, rwnd. rwnd = 0이면 멈추고 Zero Window Probe로 확인합니다.
    *   혼잡 제어(네트워크): cwnd, Slow Start(지수 증가) → AIMD(선형 증가, 손실 시 절반), 3 Duplicate ACK → Fast Retransmit/Recovery.
    *   오류 제어(데이터): 체크섬, ACK, 재전송.
    *   송신자가 한 번에 보낼 수 있는 양은 `min(rwnd, cwnd)`입니다.
*   **포트 포워딩**: **공유기(라우터)의 NAT**에서 일어납니다. 외부에서 `공인 IP:포트`로 들어온 요청을 미리 정한 규칙에 따라 `내부 사설 IP:포트`로 바꿔 전달합니다(DNAT). IP와 포트를 함께 다루므로 **L3~L4 동작**입니다.
    *   일반 NAT(NAPT)는 내부 → 외부로 나갈 때 자동으로 규칙이 생기고, 포트 포워딩은 외부 → 내부로 들어오는 연결을 위해 관리자가 미리 설정합니다.

### 🗂️ DS: Heap & Priority Queue / Hash Table

*   **Heap**: 부모가 자식보다 항상 크거나(최대 힙) 작은(최소 힙) 완전 이진 트리입니다. 삽입·삭제 O(log N), 최댓값/최솟값 조회 O(1).
*   **Priority Queue**: 우선순위가 높은 것부터 꺼내는 추상 자료형이고, 보통 Heap으로 구현합니다.
*   **Hash Table**: 해시 함수로 키를 인덱스로 바꿔 평균 O(1)에 접근합니다. 충돌 해결은 체이닝과 개방 주소법(선형·제곱 탐사, 이중 해싱).
*   **예상 질문**: 힙은 왜 배열로 구현하나요? Java HashMap은 충돌이 많아지면 왜 RB 트리로 바꾸나요? (3회차와 연결)

### 🌐 NW: HTTP vs HTTPS / SSL 핸드셰이크

*   **HTTP vs HTTPS**: HTTP는 평문이라 도청·변조에 취약하고, HTTPS는 TLS로 암호화·무결성·인증을 더합니다.
*   **TLS 핸드셰이크**: 인증서로 서버를 확인하고, 비대칭키로 세션키를 안전하게 나눈 뒤 대칭키로 통신합니다.
*   **흐름 연결**: 2회차 요청 흐름(DNS → TCP 연결 → TLS → HTTP)에서 3회차가 "TCP 연결"이었다면, 4회차는 다음 단계인 "TLS"입니다.
*   **예상 질문**: 왜 처음부터 끝까지 비대칭키로 암호화하지 않나요? 인증서는 어떻게 믿을 수 있나요?
