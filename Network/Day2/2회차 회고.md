### 🗂️ 자료구조: Tree 기초 & BST (이슈 예상 질문 기반 Q&A)

*   트리는 **연결되고 사이클이 없는 그래프**입니다. 노드가 N개면 간선은 항상 **N-1개**입니다. 루트를 뺀 모든 노드가 부모를 하나씩 가지기 때문입니다.
*   **이진 트리**는 자식이 최대 2개라는 모양 규칙이고, **BST**는 여기에 값의 정렬 규칙(왼쪽 서브트리 < 현재 노드 < 오른쪽 서브트리)을 더한 것입니다.
*   **BST 판별**은 직속 자식만 비교하면 오답입니다. 범위를 내려보내는 재귀(Min-Max)나 중위 순회가 오름차순인지 확인하는 방법을 씁니다.
*   BST는 정렬된 순서로 넣으면 **편향 트리**가 되어 탐색이 O(N)으로 퇴화합니다. 이를 막는 것이 **자가 균형 트리**(AVL, Red-Black)입니다.
*   자식이 둘인 노드를 삭제할 땐 **중위 선행자(왼쪽 최댓값)** 또는 **중위 후속자(오른쪽 최솟값)** 로 대체합니다.
*   실무 응용: id/parent\_id 목록을 해시 맵으로 O(N)에 중첩 트리로 변환, 구간 검색은 균형 BST 계열(파이썬은 sortedcontainers, 인프라는 Redis ZSET)로 해결합니다.

### 🌐 네트워크: 전체 흐름 개요 (최승우, 최나현 발표)

*   **구성**: 노드와 간선(그래프), 호스트, 네트워크 장비, 통신 매체, 메시지. 서버와 클라이언트는 기계의 종류가 아니라 **역할**입니다.
*   **범위**: LAN, CAN, MAN, WAN. 인터넷은 WAN의 대표 예시일 뿐이고, 군 국방망처럼 비공개 WAN도 있습니다.
*   **교환 방식**: 회선 교환(길을 먼저 예약, 안 쓸 때도 점유)과 패킷 교환(쪼개서 전송, 효율적이지만 지연 변동, 손실, 순서 뒤바뀜 가능).
*   **요청 흐름**: DNS로 IP 획득 → TCP 연결 → TLS → HTTP 요청 → 응답 → 렌더링.
*   **캡슐화**: 데이터에 TCP 헤더 → IP 헤더 → 링크 헤더와 FCS 순으로 붙이고, 수신 측은 반대로 벗깁니다. 라우터는 IP를 읽어 다음 장비를 정하고 **구간마다 링크 포장(MAC)을 새로 씌웁니다**.

### 🗂️ DS: 균형 트리 (AVL, Red-Black)

*   **왜 필요한가**: BST가 편향되면 O(N)으로 퇴화합니다. 균형을 유지해 높이를 O(log N)으로 지킵니다.
*   **AVL 트리**: 좌우 서브트리 높이 차(Balance Factor)를 1 이하로 엄격히 유지합니다. 불균형이 생기면 **회전 4종(LL, RR, LR, RL)** 으로 바로잡습니다. 조회가 빠르지만 삽입과 삭제 때 회전이 잦습니다.
*   **Red-Black 트리**: 노드에 색을 주고 5가지 불변 규칙으로 가장 긴 경로가 가장 짧은 경로의 2배 이하가 되게 느슨하게 유지합니다. 삽입과 삭제 때 회전이 적어 C++ `std::map`, Java `TreeMap` 등에 쓰입니다.
*   **예상 질문**: AVL과 Red-Black은 언제 무엇을 쓰나요? 회전은 왜 BST 규칙을 깨지 않나요?

### 🌐 NW: TCP vs UDP / TCP 핸드셰이크 / TCP 제어 기법 / 포트 포워딩

**TCP vs UDP**

*   TCP는 연결 지향이고 신뢰성(재전송, 순서 보장, 흐름·혼잡 제어)을 보장하며 상대적으로 느립니다.
*   UDP는 비연결이고 헤더가 단순해 빠릅니다. 스트리밍, 실시간 게임, DNS에 쓰입니다.
*   예상 질문: UDP는 신뢰성이 없는데 왜 아직도 많이 쓰이나요?

**TCP 핸드셰이크**

*   연결 수립은 **3-way**: SYN → SYN+ACK → ACK
*   연결 종료는 **4-way**: FIN → ACK → FIN → ACK, 이후 TIME\_WAIT 유지
*   예상 질문: 연결은 3-way인데 종료는 왜 4-way인가요? TIME\_WAIT는 왜 필요한가요?

**TCP 제어 기법**

*   **흐름 제어**: 송신자와 수신자의 처리 속도 차이를 조절합니다 (Stop and Wait, 슬라이딩 윈도우).
*   **혼잡 제어**: 네트워크가 넘치지 않게 전송량을 조절합니다 (Slow Start, AIMD, 혼잡 회피, 빠른 회복).
*   **오류 제어**: 손실되거나 깨진 패킷을 재전송합니다 (Go-Back-N, Selective Repeat).
*   예상 질문: 슬라이딩 윈도우의 동작 원리는? Slow Start와 AIMD의 차이는?

**포트 포워딩 (2회차 이슈 질문에서 이어짐)**

*   **왜 외부에서 바로 접속이 안 되나**: 사설 IP(192.168.x.x, 10.x.x.x)는 공인 인터넷에서 라우팅되지 않고, 공유기는 내부에서 시작하지 않은 외부발 SYN을 기본적으로 차단합니다.
*   **포트 포워딩**: 공유기에 "공인 IP의 특정 포트로 온 트래픽을 내부 사설 IP의 특정 포트로 넘겨라"는 고정 규칙을 넣는 것입니다. 들어올 때 목적지를 바꾸고(DNAT), 응답은 출발지를 공인 IP로 바꿔(SNAT) 내보냅니다.
*   **NAPT(PAT)**: 여러 기기가 공인 IP 하나를 나눠 쓸 때, IP뿐 아니라 **포트 번호까지 변환**하고 변환 테이블로 응답을 정확한 기기에 돌려줍니다.
*   **TCP와의 연결**: 포트는 전송 계층(TCP/UDP)의 주소이고, 포트 포워딩과 NAPT는 이 포트를 변환하는 기술입니다. 그래서 TCP vs UDP와 함께 보면 자연스럽습니다.
*   **꼬리 질문**: ngrok 같은 터널링 도구는 어떻게 공유기 설정 없이 외부에 공개하나요? (내 PC가 외부 중계 서버로 먼저 연결을 맺는 방식) 포트가 고갈되면? (CGNAT에서는 공인 IP를 풀로 묶어 분산)
