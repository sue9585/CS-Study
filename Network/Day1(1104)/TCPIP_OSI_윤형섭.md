## 1. 개요 및 정의

> OSI 7계층과 TCP/IP 4계층의 차이와 계층별 네트워크 데이터 전송 흐름을 정리.

- **OSI 7계층(OSI 7 Layers)**: 국제표준화기구(ISO)에서 네트워크 통신 과정을 7단계로 세분화하여 정의한 **표준 참조 모델**이다. 물리적인 신호 전달부터 사용자 애플리케이션까지의 역할을 독립적인 계층으로 나눈다.
- **TCP/IP 4계층(TCP/IP Protocol Suite)**: 실제 인터넷 통신에서 표준으로 사용되는 **실무 중심의 프로토콜 모델**이다. OSI 7계층의 일부 계층을 통합하여 4단계(응용, 전송, 인터넷, 네트워크 인터페이스)로 구성한다.
- **등장 배경**: 과거에는 하드웨어·소프트웨어 제조사마다 통신 규격이 달라 이기종 시스템 간 통신이 어려웠다. 이를 해결하기 위해 공통 참조 기준인 OSI 7계층이 제정되었고, 계층을 분리함으로써 통신 과정을 단계별로 파악하고 장애 발생 시 해당 계층만 독립적으로 점검할 수 있게 되었다. 한편 실무 인터넷 환경에서는 먼저 개발되어 검증된 TCP/IP 모델이 사실상의 표준으로 자리 잡았다.

## 2. 핵심 동작 원리 및 특징

> 추상적인 계층 정의만 외우기보다, 익숙한 Python 소켓(Socket) 통신 코드와 캡슐화 흐름을 기준으로 구조를 이해하려고 함.

- **캡슐화(Encapsulation)**: 송신 측에서 상위 계층부터 하위 계층으로 내려가며 각 계층의 제어 정보인 **헤더(Header)**(데이터 링크 계층은 트레일러 포함)를 데이터에 붙이는 과정이다.
  `Data → Segment(TCP 헤더) → Packet(IP 헤더) → Frame(MAC 헤더·트레일러) → Bit(0과 1)`
- **역캡슐화(Decapsulation)**: 수신 측에서 하위 계층부터 상위 계층으로 올라가며 각 계층의 헤더를 순서대로 해석하고 제거하여 원본 데이터를 복원하는 과정이다.

**Python으로 이해한 예시**

```python
import socket

# [전송 계층 - TCP] IPv4(AF_INET)와 TCP(SOCK_STREAM) 기반 소켓 생성
client_socket = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

# [인터넷 계층 - IP / 전송 계층 - Port] 목적지 IP와 포트(80)로 연결 수립 (3-Way Handshake)
client_socket.connect(("93.184.216.34", 80))

# [응용 계층 - HTTP] 요청 메시지 전송 → OS 커널을 거치며 하위 계층 헤더가 캡슐화됨
request = b"GET / HTTP/1.1\r\nHost: example.com\r\n\r\n"
client_socket.sendall(request)

# [역캡슐화] 하위 계층 헤더가 제거되고 복원된 응용 계층 응답 데이터 수신
response = client_socket.recv(1024)
print(response.splitlines()[0])  # b'HTTP/1.1 200 OK'
client_socket.close()
```

**계층별 매핑 및 핵심 역할**

| TCP/IP 4계층        | OSI 7계층        | 데이터 단위 (PDU)   | 주요 프로토콜 / 장비      | 핵심 역할                                           |
| :------------------ | :--------------- | :------------------ | :------------------------ | :-------------------------------------------------- |
| 응용 (Application)  | 7. 응용          | Data (Message)      | HTTP, DNS, FTP, SMTP      | 사용자와 직접 상호작용하는 애플리케이션 서비스 제공 |
| 응용 (Application)  | 6. 표현          | Data                | SSL/TLS, UTF-8, JPEG      | 데이터 인코딩·디코딩, 압축, 암호화·복호화           |
| 응용 (Application)  | 5. 세션          | Data                | RPC, NetBIOS, Socket 세션 | 통신 양단 간 논리적 연결 생성·유지·종료             |
| 전송 (Transport)    | 4. 전송          | Segment / Datagram  | TCP, UDP / L4 스위치      | 포트(Port) 기반 프로세스 간 전송, 신뢰성·흐름 제어  |
| 인터넷 (Internet)   | 3. 네트워크      | Packet              | IP, ICMP / 라우터         | 논리 주소(IP) 지정 및 목적지까지 최적 경로 라우팅   |
| 네트워크 인터페이스 | 2. 데이터 링크   | Frame               | Ethernet / L2 스위치      | 물리 주소(MAC) 기반 인접 장비 간 전송, 오류 검출    |
| 네트워크 인터페이스 | 1. 물리          | Bit                 | 케이블, 허브, 리피터      | 데이터를 전기·광 신호(0과 1)로 변환하여 물리적 전송 |

**두 모델 비교**

| 구분          | OSI 7계층                            | TCP/IP 4계층                              |
| :------------ | :----------------------------------- | :---------------------------------------- |
| 목적          | 통신 전반의 표준화 및 교육·분석 기준 | 실제 인터넷 프로토콜 구현 및 운용         |
| 접근 방식     | 역할 중심의 이론적 참조 모델         | 프로토콜 중심의 실무 구현 모델            |
| 상위 계층 구조| 응용·표현·세션 3개 계층으로 세분화   | 응용 계층 1개로 통합                      |
| 하위 계층 구조| 데이터 링크·물리 2개 계층으로 분리   | 네트워크 인터페이스 계층 1개로 통합       |
| 주 활용처     | 네트워크 장비 구분(L2/L4/L7), 장애 진단 | 실제 OS 네트워크 스택 및 인터넷 통신 전반 |

※ 최근 네트워크 교재에서는 TCP/IP의 네트워크 인터페이스 계층을 물리 계층과 데이터 링크 계층으로 나누어 **TCP/IP 5계층**으로 설명하기도 한다.

## 3. 실무 / 면접 핵심 포인트

### Q1. 네트워크 모델을 여러 계층으로 나누는 이유를 설명하시오.

- **A**: 복잡한 통신 과정을 단계별로 모듈화하여 데이터의 흐름을 파악하기 쉽고, 특정 계층에 장애나 기술 변경이 발생하더라도 다른 계층에 영향을 주지 않고 해당 계층만 독립적으로 수정·유지보수할 수 있기 때문입니다. 또한 계층별 표준 규격만 맞추면 서로 다른 제조사의 장비나 소프트웨어 간에도 호환성이 보장됩니다.

### Q2. OSI 7계층이 존재함에도 실무에서 TCP/IP 4계층을 주로 사용하는 이유를 설명하시오.

- **A**: OSI 7계층은 이론적 표준을 먼저 정의한 참조 모델인 반면, TCP/IP는 실제 인터넷 환경에서 먼저 동작하며 검증된 프로토콜 기반 모델이기 때문입니다. 특히 실제 애플리케이션 개발에서는 세션 관리, 인코딩·암호화, 응용 프로토콜 처리가 명확히 분리되기보다 하나의 프로그램 내부에서 함께 처리되는 경우가 많아, 이를 응용 계층 하나로 묶은 TCP/IP 4계층이 실무 구조와 더 잘 맞습니다.

### Q3. 전송 계층의 TCP와 UDP는 어떤 차이가 있는지 설명하시오.

- **A**: TCP는 연결 지향형 프로토콜로, 3-Way Handshake를 통해 연결을 맺고 데이터의 순서 보장, 재전송, 흐름·혼잡 제어를 수행해 신뢰성을 보장합니다. 반면 UDP는 비연결형 프로토콜로, 연결 설정이나 재전송 과정이 없어 신뢰성은 보장하지 않지만 헤더 구조가 단순하고 전송 속도가 빨라 실시간 스트리밍이나 온라인 게임 등에 적합합니다.

### 실제 활용 사례

**OSI 7계층 - 웹사이트 접속 장애 트러블슈팅**

특정 서버에 접속이 안 될 때 하위 계층부터 상위 계층 순서로 원인을 좁혀 나가는 상황에 적합하다.

- 랜선·와이파이 신호 문제면 1~2계층, `ping`(ICMP) 테스트 실패나 라우팅 문제면 3계층(네트워크) 문제로 진단 가능
- 서버 포트가 닫혀 있으면 4계층(전송), 연결은 되지만 `500 Internal Server Error`가 반환되면 7계층(응용) 문제로 분리해 대응

**TCP/IP 4계층 - 웹 브라우저의 HTTP 요청 전송**

사용자가 브라우저에서 웹 페이지를 요청할 때 애플리케이션과 OS 네트워크 스택이 동작하는 상황을 예시로 정리했다.

- 응용 계층에서 HTTP 메시지를 생성하면, OS 커널의 전송 계층(TCP)에서 포트 번호를 붙여 세그먼트로 분할
- 인터넷 계층(IP)에서 목적지 IP로 경로를 잡고, 네트워크 인터페이스 계층에서 MAC 주소를 통해 다음 라우터로 프레임을 전달

### 학습하며 느낀 점

막연하게 외우던 계층 이름을 Python의 `socket` 코드에 대입해 보며, 개발자가 작성하는 애플리케이션 코드(응용 계층) 아래에서 OS가 TCP 세그먼트와 IP 패킷으로 데이터를 감싸 전달하는 흐름을 정리했다.

OSI 7계층은 통신 역할과 장애 지점을 정교하게 구분하기 위한 **참조 모델**이고, TCP/IP 4계층은 실제 인터넷 프로토콜이 맞물려 돌아가는 **실무 모델**이라는 역할 차이가 핵심이었다.

특히 **실제 통신은 TCP/IP 기반으로 동작하더라도, 실무에서 L4/L7 로드밸런서를 구분하거나 네트워크 장애 원인을 공유할 때는 여전히 OSI 7계층이 공통 언어로 쓰인다**는 점을 확인했다.
